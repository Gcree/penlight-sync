## Findings and resolution

- The direct RGB encoder uses the public [LightStickCommandBuilder](https://github.com/Polyfish0/abo-light-stick-app/blob/master/app/src/main/java/de/polyfish0/adolightstick/LightStickCommandBuilder.kt) AES-128 ECB frame: one 16-byte plaintext block with fixed prefix/suffix and three RGB bytes. PenlightProtocol.swift:13-45 checks encryption status and output length. Swift self-tests compare red, green, blue, black, and white frames to known vectors.
- The connected-peripheral path now calls CoreBluetooth connect before service discovery (PenlightSync.swift:382-388, 422-439). This resolves the observed GATT setup timeout; [Apple's retrieveConnectedPeripherals documentation](https://developer.apple.com/documentation/corebluetooth/cbcentralmanager/retrieveconnectedperipherals%28withservices%3A%29) requires a local connect before use.
- Writes remain restricted to the explicit CoreBluetooth identifier, exact Ado Light Stick name, service 0000, and a writable characteristic 0000. The CLI serializes writes, waits for write-with-response acknowledgement, bounds shutdown, and fails if a sync ends without an acknowledged screen write (PenlightSync.swift:300-302, 526-549, 709-775).
- Earlier findings on replay shutdown, pending-write false success, unexpected disconnect, post-timeout sampling, prepared ATT write accounting, and main-display fallback are resolved in current source.

## Subsequent live stall: continuous sync not yet accepted

**P1 — A single stalled screenshot await silently stops all later color updates.** In `PenlightSync.swift:574-609`, `sampleAndMaybeWrite()` sets `sampling = true` and clears it only after `ScreenColorSampler.sample()` returns or throws. The repeating timer at `PenlightSync.swift:522-524` skips every tick while that flag remains true. The sampler awaits both content enumeration and screenshot capture (`ScreenColor.swift:38-58`), with no per-sample deadline or stage diagnostics. A hung await therefore leaves the BLE connection and CLI alive but prevents every later screen update. This is a definite control-flow failure; which underlying await, if either, hung in the live run remains unproven.

After the earlier Terminal-host fixture, the parent reported a later fresh 15-second full-main-screen color fixture with no new RGB write or acknowledgement in the still-running Terminal process. A concurrent new CLI session reached GATT sync active but emitted no sample/write lines and exited with code 2 after 20 seconds. Both observations are consistent with a stalled sampler, though they do not locate it or exclude an OS capture-service issue. The parent is gathering a bounded standalone screenshot probe and process sample; the reviewer did not run hardware or OS capture. Until a watchdog/recovery path and a repeated live fixture are verified, the earlier short fixture cannot establish sustained sync reliability.

Subsequent parent diagnostics: a standalone eight-second `ScreenColorTests --capture` completed immediately with `#1A191A`; a separate instrumented CLI reached GATT sync and completed roughly 35 enumeration-plus-image cycles with an acknowledged first RGB write. The old Terminal process alone still appeared stalled. The parent also rebuilt the executable on disk while that process was running; any effect of replacing a live executable on its capture service connection is unproven. A controlled repeat should use one stable binary without rebuilding it during the run, continue past two minutes, and then repeat the full-screen color fixture. These diagnostics narrow the incident but do not remove the code-level no-watchdog failure path.

The smallest safe correction is to add phase-specific timing/diagnostics and a bounded sample deadline that surfaces a real failure instead of silently freezing. For continuous capture, Apple documents [`SCStream`/`SCStreamOutput`](https://developer.apple.com/documentation/screencapturekit/scstream) as the frame-delivery API, while [`SCScreenshotManager`](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager) captures individual frames. A persistent stream may avoid repeated enumeration and one-shot capture, but it should be selected after the current stall is localized and tested on the Terminal host.
