# Ado 手燈螢幕連動

[English](README.en.md) ｜ 中文

擷取主螢幕的平均色（自動略過黑邊與字幕），透過藍牙（BLE）直接控制自己的 Ado Light Stick，讓手燈跟著影片變色。提供 Mac 與 Windows 視窗版，以及 Mac 命令列工具。連動時不需要網路、手機或官方 App（只有「檢查更新」會連到 GitHub，可關閉）。

## 下載

到 [Releases](https://github.com/Gcree/penlight-sync/releases) 下載：

- `PenlightSync-macOS.zip`：macOS 14 以上（Apple 晶片與 Intel 都可用）。
- `PenlightSync-Windows-x64.zip`：Windows 10（2004 版）或 11，已內含 .NET，不需另外安裝。

## 視窗版

兩個版本的畫面相同，配色會跟隨系統的淺色／深色模式（深色與 App 圖示同一套深藍紫色）：

![Mac 版深色模式](docs/screenshots/mac-dark.png)

- **上方即時卡片**：狀態標籤（待機／連線中／連動中…）、延遲數字，以及「螢幕平均色 → 手燈目前顏色」兩個色塊（手燈色塊只在手燈回報收到指令後才更新）。下方選擇手燈、「掃描」與「開始連動／停止連動」；上次選的手燈會被記住。
- **下方設定分頁**：「色彩」「動態」「取色範圍」「一般」四頁。每個滑桿右邊會顯示數值，調整過的滑桿旁會出現「↺」可一鍵恢復預設；「一般」頁有檢查更新、執行記錄（可展開）與「全部重設」（色彩與動態恢復預設，手燈與取色範圍不變）。
- **風格預設**（色彩頁）：一鍵套用鮮豔度、最低亮度、整體亮度與色溫的組合——自然、標準（預設值）、鮮豔、演唱會、電影院；套用後仍可再微調。
- **取色範圍**：預設是整個主螢幕；按「框選範圍…」後拖曳框出影片所在的區域（按 Esc 取消），手燈就只跟那塊畫面變色，適合影片沒有全螢幕時使用。按「整個螢幕」改回。設定會被記住，連動中也能改。
- **斷線自動重連**：連動中手燈斷線或藍牙寫入失敗時，會保留目前的燈光狀態並自動重新連線最多 30 秒；連不上才停止並顯示原因。若一直連不上，可長按手燈背面按鈕進入配對模式。
- **延遲顯示**：連動中狀態下方每 5 秒顯示一次近期平均的「畫面擷取」與「藍牙來回」時間（毫秒），約每 30 秒也會寫進執行記錄，方便比較設定前後的差異。
- **檢查更新**：開啟時會向 GitHub 查詢最新版本號（預設開啟，可在「一般」頁關閉「啟動時檢查更新」），有新版本就跳出提示，可選「前往下載」、「略過這個版本」或「稍後」；也可隨時按「立即檢查」。只讀取版本號，不傳送任何資料；沒有網路時不會報錯。新版需自行下載並取代舊版（Mac 版更新後要重新允許藍牙與螢幕錄製權限）。
- **燈光效果**（連動中也能即時調整，設定會被記住）：
  - **低延遲模式**（預設關閉）：把漸變時間限制在最多 0.15 秒（滑桿設得更短則照滑桿），讓手燈緊跟畫面；代價是換色比較硬、沒那麼柔和。
  - **鮮豔度**（0～100%，預設 40%）：影片平均色常偏灰，這裡把顏色調得更飽和，色相與亮度不變；本來就很鮮豔或接近灰白的顏色幾乎不受影響。
  - **最低亮度**（0～50%，預設關）：暗場時手燈至少保持這個亮度（保留原本色相，全黑則顯示微弱白光），避免黑畫面時手燈完全熄滅。
  - **整體亮度**（10～100%，預設 100%）：整支手燈的亮度上限，在暗的房間覺得太刺眼時調低。套用在最低亮度之後。
  - **色溫**（冷 50～暖 50，預設中性）：往暖調會減弱藍與綠、往冷調會減弱紅與綠，讓燈光偏暖黃或偏冷藍；只會變暗、不會讓顏色爆掉。
  - **漸變時間**（0～2 秒，預設 0.6 秒）：換色時柔和淡入淡出，數值是大約完成 95% 變化所需的時間；設為 0 則立即換色。數值越大越柔和，越小越跟拍。
  - **換場快切**（預設開啟）：畫面大幅換色（例如剪接換場）時，改用約五分之一的漸變時間快速跟上，小幅變化仍照常柔和漸變。
  - **呼吸律動**（預設關閉）：畫面顏色穩定時，手燈亮度以約 4 秒一次緩慢起伏（最暗約 70%）；畫面一換色就自動退場，不會干擾影片節奏。
  - **跟音樂節拍閃動**（預設關閉）：聆聽電腦正在播放的聲音，偵測大鼓節拍；有節拍時手燈平常稍暗（約 55%），每一拍亮回全亮，畫面上會顯示偵測到的 BPM。燈光快慢也會跟著 BPM 自動調整：以 120 BPM 為基準，快歌（最多約 0.6 倍漸變時間）換色更俐落、慢歌（最多約 1.4 倍）更柔和，每次閃光大約持續三分之一拍。音樂停約 2 秒後自動恢復一般亮度，播放音樂時呼吸律動會暫停。聲音只在記憶體中分析，不錄音也不上傳。Mac 版使用同一個「螢幕與系統錄音」權限；Windows 版不需額外權限。

### Mac

1. 關閉手機上的 Ado App，長按手燈背面按鈕至藍燈閃爍。
2. 打開「Ado 手燈連動」。第一次開啟時，系統會詢問藍牙權限，請按「允許」。
3. 按「掃描」→ 在選單選手燈 → 按「開始連動」。
4. 第一次連動需要螢幕錄製權限：到「系統設定 › 隱私權與安全性 › 螢幕與系統錄音」允許本 App；清單裡沒出現時，按「+」手動加入 App。允許後請**結束並重新開啟 App**。
5. 按「停止連動」中斷連線，手燈就能再交給手機 App 使用。

App 是自簽（未經 Apple 公證）。若被擋，請在 Finder 對 App 按右鍵 →「打開」。每次重新編譯後，系統會把它當成新 App，需要重新允許藍牙與螢幕錄製權限。

### Windows

把 `PenlightSync.exe` 放到 Windows 電腦雙擊執行，操作與 Mac 相同。電腦需要支援並開啟藍牙；不需要先在 Windows 設定裡配對手燈。

- 首次執行若出現「Windows 已保護您的電腦」，按「其他資訊」→「仍要執行」（程式沒有付費簽章）。
- 記錄檔：`%LOCALAPPDATA%\PenlightSync\latest.log`。

### 使用建議

- 讓影片全螢幕，或用「框選範圍…」框住影片，平均色才會接近影片本身。上下／左右的黑邊會自動略過，畫面下方四分之一的白色字幕不計入，畫面中央的權重約是角落的兩倍。
- 取的是**主螢幕**上的畫面，不是單一瀏覽器分頁；框選範圍固定在螢幕上的位置，移動影片視窗後請重新框選。
- 畫面持續擷取（每秒最多約 30 次；Mac 只在畫面有變化時才送來新畫面），一有新顏色就立刻計算燈光；藍牙每收到手燈的回覆就馬上送下一筆，只送出改變的顏色，不儲存或上傳畫面。
- 藍牙延遲：這支手燈只接受「送出後等回覆」的寫法，每筆指令都要等一次來回，無法再省。Windows 11 會額外向系統要求較短的藍牙連線間隔（手燈可能不接受，結果寫在執行記錄）；Mac 沒有讓 App 調整連線間隔的方法。

## 命令列版（Mac）

1. 關閉手機上的 Ado App；讓手燈背面按鈕長按至藍燈閃爍。
2. 雙擊 `開始連動.command`。若系統要求，允許藍牙及螢幕錄製權限。
3. 在啟動的終端視窗按 **Control-C** 停止。單次最長執行一小時。

首次從終端機啟動時，請在系統設定允許**終端機的螢幕錄製權限**，再結束並重新開啟終端機。若啟動失敗，錯誤會保留在視窗，並記錄於 macOS 暫存資料夾的 `ado-penlight-sync/latest.log`。

啟動檔只連線 `device-id.txt` 指定的那支手燈。裝置 ID 每台 Mac 不同，請先執行 `./PenlightSync --probe`，把 `PROBE_OK identifier=` 後面的值存成本資料夾的 `device-id.txt`（此檔不納入版本控制）。命令列版使用相同的平均色取樣（含略過黑邊與字幕），每秒最多寫入四次，沒有視窗版的燈光效果。

`--probe` 只讀取服務；`--rgb RRGGBB --device UUID` 送出單色；`--calibrate --device UUID` 接受已觀察的十六進位指令，供診斷使用。

## 已驗證的範圍

- 協議：紅／綠／藍／熄滅指令與實際擷取封包一致；新生成的白／青／熄滅指令經實機確認。
- Mac 命令列版與 Mac 視窗版：以全主螢幕紅→綠→藍→白→黑色塊實測，五色均取得手燈寫入回應，使用者確認手燈實體依序變色。掃描、連動、停止皆經實機驗證。詳見 `驗證紀錄.md`。
- Windows 版：加密指令、平均色與燈光效果（含節拍偵測）的核心邏輯以與 Mac 版相同的測試案例驗證；**尚未在實體 Windows 電腦上執行**，系統聲音擷取也尚未實測。
- v1.2.0 新增的鮮豔度、最低亮度、黑邊／字幕略過、換場快切與節拍閃動只經過自動測試，**尚未用手燈實機驗證**。
- v1.3.0 新增的框選取色範圍、斷線自動重連與依 BPM 調整快慢，以及之後的連續擷取、低延遲模式、延遲顯示與 Windows 11 藍牙連線參數，只經過自動測試與編譯，**尚未用手燈實機驗證**。
- v1.5.0 新增的檢查更新：版本比較邏輯以 Swift／C# 相同測試案例驗證，並確認 GitHub 最新版查詢可取得版本號；新版提示視窗尚未在實際有新版本時操作過，Windows 版也尚未在實體電腦上執行。
- v1.6.0 的新介面、風格預設、整體亮度與色溫：燈光運算以 Swift／C# 相同測試案例驗證；Mac 版已實際開啟並截圖確認淺色與深色模式、四個分頁與預設套用。**Windows 版新介面只確認可以編譯，尚未在實體電腦上看過**，版面可能需要微調。新參數尚未用手燈實機驗證。
- 尚未驗證：長時間影片播放。螢幕擷取或單筆寫入超過 8 秒未完成時，會停止並顯示錯誤。

## 原始碼與檢查

```sh
./build_mac_app.sh                                    # 產生 dist/PenlightSync.app
swiftc -parse-as-library ScreenColor.swift PenlightProtocol.swift PenlightSync.swift -o PenlightSync   # 命令列版
python3 -m unittest discover -s . -p 'test_*.py' -v   # 全部測試
cd windows && dotnet publish PenlightSyncWin -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true -p:DebugType=none -o ../dist/windows
```

Windows 版需 .NET 8 SDK，可在 Mac 上直接交叉編譯。

- `ScreenColor.swift`：主螢幕擷取設定與平均色（命令列版用單張截圖，視窗版用 `PenlightApp/ScreenStream.swift` 連續擷取）；`PenlightProtocol.swift`：RGB 指令加密；`PenlightSync.swift`：命令列工具。
- `PenlightApp/`：Mac SwiftUI 視窗、控制邏輯、`LightEngine.swift`（鮮豔度、最低亮度、漸變、換場、呼吸、節拍）、`BeatDetector.swift`（節拍偵測）與 `SystemAudioMonitor.swift`（系統聲音）。
- `windows/PenlightCore/`：上述演算法的 C# 移植；`windows/PenlightCore.Tests/` 用與 Swift 相同的案例檢查。
- `windows/PenlightSyncWin/`：WinForms 視窗、Windows 藍牙（WinRT，Windows 11 會要求較短連線間隔）、螢幕擷取（GDI StretchBlt 直接縮圖）與系統聲音擷取（WASAPI，使用 MIT 授權的 NAudio）。
- `test_*.py`：編譯並執行 Swift／C# 自我測試、啟動檔與命令列測試。
