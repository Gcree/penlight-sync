寫於 2026-10-26。使用者已經選定做法：**PenlightSync 加一個「網站模式」，網站把現在的顏色和拍點傳給它**。這份計畫給新的對話照著做，不需要再讀之前的對話。

### 兩個專案

|---|---|---|
| 位置 | `/Users/forai/Documents/Codex/2026-10-23/library-application-support-agent-room-dm/outputs/penlight-sync` | `/Users/forai/Documents/Claude/ado-guide` |

### 已經有、可以直接用的東西

- **PenlightSync 的燈光引擎** `PenlightApp/LightEngine.swift`：`setTarget(_ rgb:)` 設定目標色，`beat(strength:bpm:)` 送一個拍子，`step(dt:)` 算出要寫進手燈的顏色。鮮豔度、亮度、色溫、漸變、亮滅、換色、呼吸都在裡面。Windows 版的同一套邏輯在 `windows/PenlightCore/PenlightCore.cs`。
- **PenlightSync 的流程** `PenlightApp/PenlightController.swift`：手燈連上後（約第 430 行）呼叫 `startScreenStream()`，開了節拍同步就再呼叫 `startAudio()`；`screenSampled` 收到顏色就 `engine.setTarget`，`startAudio` 收到拍子就 `engine.beat`。網站模式就是**換掉這兩個來源**。
- **網站的資料**（`ado-guide/songs.js` 和 `app.js`）：
  - `penOf(S).cols`：這首的螢光棒顏色（色碼陣列，例如〈踊〉是紅、藍；沒指定時是藍，`penOf(S).none` 為 true）。
  - `BEAT[id] = [BPM, 第一個小節第一拍的秒數, 小節第一拍可不可信]`，`beatAt(t)` 算出現在是第幾拍。有 5 首沒有拍點資料。
  - `CLIMAX[id]`：副歌高潮秒數（網站在這時噴彩帶）。
  - `cueAt(t)`：這一句的動作（拍手、大合唱…），`listen` 表示安靜聽。
  - `now()`、`isPlaying()`、`RATE`（0.5／0.75／1 倍速）、`S`（目前的歌）。
  - 每一格畫面都會跑的 `frame()`（`app.js` 最後面）。
  - 練習工具選單 `#tools`，開關都存在 localStorage 的 `tool-*`（`TOOL` 物件）。

### 整體做法

```
網站（瀏覽器）──WebSocket──▶ PenlightSync（只聽 127.0.0.1）──藍牙──▶ 手燈
   送：哪首歌、播到幾秒、有沒有在播、速度、顏色、拍點、高潮時間、這句的動作
```

- 網站**不直接送每一拍**，只送「狀態」：有變化就送，另外每秒送一次校時。PenlightSync 自己用「播到幾秒＋經過時間×速度」推算現在的影片時間，再算出每一拍，這樣不會因為網路延遲讓拍子亂掉。
- 協議細節以第 1 節為準，兩邊都照這份寫。

## 1. 傳輸協議 v1（兩邊共用，改之前先改這一節）

- 位址：`ws://127.0.0.1:51730/ado`。PenlightSync **只綁 127.0.0.1**，不能綁 `0.0.0.0` 或區網位址。
- 來源檢查：PenlightSync 只接受 `Origin` 是 `https://gcree.github.io`，或 `http://localhost:<任意埠>`、`http://127.0.0.1:<任意埠>`（本機開發用）。其他來源直接拒絕連線。
- 同時只服務一個網頁：新的連線進來就關掉舊的。
- 每則訊息是一個 JSON 物件，上限 4 KB；看不懂的 `type` 或 `v` 不是 1 就忽略，不能讓程式當掉。

### 網站 → PenlightSync

```json
{
  "v": 1, "type": "state", "seq": 42,
  "song": "odo", "title": "踊",
  "playing": true, "t": 83.42, "rate": 1,
  "colors": ["#ff4a5a", "#5d9dfe"], "colorsSet": true,
  "beat": { "bpm": 128, "offset": 1.858, "barKnown": true },
  "climax": 169.11,
  "cue": "clap"
}
```

| 欄位 | 說明 |
|---|---|
| `seq` | 每送一則加 1，PenlightSync 收到比較舊的就丟掉 |
| `t` | 送出當下的影片秒數（`now()`），小數兩位 |
| `rate` | 0.5、0.75 或 1 |
| `colors` / `colorsSet` | `penOf(S).cols`；`colorsSet` 是 `!penOf(S).none`（沒指定時網站用藍，手燈也用藍） |
| `beat` | 這首沒有拍點資料時是 `null` |
| `climax` | 沒有時是 `null` |
| `cue` | 這句的主要動作：`sing`、`clap`、`wave`、`jump`、`call`、`gesture`、`listen`；整首沒有逐行應援時是 `free`；前奏或還沒開始是 `""` |

什麼時候送：換歌、播放／暫停、速度改變、`cue` 改變、偵測到跳轉（實際秒數和推算秒數差超過 0.3 秒），以及每 1 秒送一次。一秒最多 5 則。

離開歌曲頁、關掉連動開關、關閉分頁（`pagehide`）時送：`{ "v": 1, "type": "stop" }`。

### PenlightSync → 網站

連上後、以及手燈狀態改變時送：

```json
{ "v": 1, "type": "hello", "app": "PenlightSync", "version": "1.7.0", "lamp": "linked" }
```

`lamp`：`linked`（手燈連著、正在跟網站）、`connecting`、`idle`（App 開著但手燈沒連）。網站只拿來顯示狀態。

## 2. 燈光怎麼跟網站走（網站模式）

寫成一個不碰藍牙、不碰網路的純函式，方便測試：輸入「最新狀態＋收到它的時間＋現在時間」，輸出「目標色」和「這一格要不要送拍子、強度多少」。建議新檔 `PenlightApp/SiteLight.swift`（Windows 移植到 `PenlightCore.cs`）。

1. **推算影片時間**：`播放中 ? t + (現在 − 收到時間) × rate : t`。
2. **顏色**：輪流使用 `colors`。有拍點時**每一小節（4 拍）換下一個顏色**；沒有拍點時每 4 秒換一次。只有一個顏色就一直用它。
3. **拍子**：有 `beat` 時，影片時間每跨過一拍就呼叫一次 `engine.beat(strength:bpm:)`，`barKnown` 為 true 且是小節第一拍時強度 1，其他拍 0.6；`bpm` 照網站給的。沒有 `beat` 就不送拍子。
4. **動作**：
   - `cue` 是 `listen`：不送拍子，亮度降到大約一半（安靜聽）。
   - 從 `climax` 開始的 8 拍（沒有拍點就 4 秒）：強制用「亮滅」效果、全亮，對應網站噴彩帶。
   - 其他動作照使用者在 App 裡選的節拍效果（加亮／亮滅／換色／自動）。「換色」效果在網站模式下改成**換到下一個網站顏色**，不用色相旋轉。
5. **暫停**：顏色停在目前這一色，不送拍子。
6. **斷線或超過 5 秒沒收到訊息**：保持最後的顏色、亮度降到 30%，畫面顯示「等待網站…」。收到新的 `state` 就恢復。
7. 鮮豔度、最低亮度、整體亮度、色溫、漸變時間這些設定在網站模式也照樣生效（顏色一樣經過 `setTarget` 的調色）。

## 3. 步驟

### 步驟 1：先確認瀏覽器願不願意連（做完才往下）

**為什麼：**網站是 https，PenlightSync 是本機的 ws。Chrome 和 Edge 通常允許連 `127.0.0.1`，但較新的 Chrome 可能會跳出「允許這個網站存取本機裝置」的詢問；Safari 可能直接擋。這一步決定支援哪些瀏覽器。

- 在 PenlightSync 寫最小的 WebSocket 伺服器（步驟 2 的 `SiteLink.swift` 骨架即可）：照第 1 節檢查 Origin，收到訊息就印出來。
- 打開 <https://gcree.github.io/ado-guide/>，在開發者工具的 Console 執行：

  ```js
  const w = new WebSocket("ws://127.0.0.1:51730/ado"); w.onopen = () => { w.send('{"v":1,"type":"stop"}'); console.log("OPEN"); }; w.onerror = e => console.log("ERR", e);
  ```

- 分別在 **Chrome、Safari、Edge（有的話）** 試，記錄：能不能連上、有沒有跳權限詢問、詢問的字樣。再用 `http://localhost:8000`（本機開網站）試一次。
- 用另一個來源（例如 `https://example.com` 的 Console）試，確認**會被拒絕**。

**做完的標準：**結果表寫進 `docs/dev/驗證紀錄.md`。**Chrome 連不上就停下來問使用者**；只有 Safari 不行就繼續，文件寫明「請用 Chrome 或 Edge」。

### 步驟 2：Mac 版接收網站資料

**改的檔案：**新增 `PenlightApp/SiteLink.swift`（WebSocket 伺服器與訊息解析）、`PenlightApp/SiteLight.swift`（第 2 節的純函式）；修改 `PenlightApp/PenlightController.swift`、`PenlightApp/PenlightApp.swift`、`build_mac_app.sh` 和 `tests/test_gui_builds.py` 的檔案清單；新增 `tests/SiteLightTests.swift`。

- 伺服器用 Network.framework 的 `NWListener`＋`NWProtocolWebSocket`，`requiredLocalEndpoint` 設成 `127.0.0.1:51730`；在 `setClientRequestHandler` 檢查 `Origin`。
- 埠被佔用時不要當掉：狀態顯示「網站連動用的連接埠 51730 被別的程式佔用」，螢幕模式照常能用。
- 「色彩」頁最上面加「取色來源」：`螢幕`／`網站（Ado 應援預習）`，記在 UserDefaults，**預設是螢幕**。
- 選「網站」時：不啟動螢幕擷取、不啟動系統聲音，不需要螢幕錄製權限；「取色範圍」頁顯示「網站模式不需要框選」。上方卡片的「螢幕平均色」色塊改成「網站顏色」，旁邊顯示歌名和「播放中／暫停／等待網站…」。
- 連動中也能切換來源，切換時重新接上對應的來源，不用重連手燈。
- 只有手燈連著、而且選了網站模式時才開伺服器；停止連動或切回螢幕就關掉。

**做完的標準：**

- `SiteLightTests.swift` 至少涵蓋：時間推算（播放、暫停、0.5 倍速）；128 BPM 下 10 秒內送出的拍數和小節第一拍；每小節換色；沒有拍點時每 4 秒換色；`listen` 不送拍子；高潮 8 拍；舊的 `seq` 被丟掉；5 秒沒收到訊息進入等待；壞掉的 JSON、超過 4 KB、`v: 2` 都被忽略。
- `SiteLink` 的測試：不在白名單的 Origin 被拒絕（可以用 `URLSessionWebSocketTask` 從同一支測試程式連自己）。
- 選螢幕模式時，行為和 v1.6.0 完全一樣（原本的測試全部通過）。

### 步驟 3：網站送資料

**改的檔案（ado-guide）：**`app.js`、`index.html`、`style.css`、`README.md`。**不能改** `songs.js`、`song-lyrics.js`、`scripts/build.mjs`。

- 練習工具選單（`#tools` 裡的 `.view-opts`）加一個開關 `<button data-tool="lamp" id="tool-lamp" aria-pressed="false">連動手燈</button>`，沿用 `TOOL` 和 `tool-*` 的存法（新的鍵是 `tool-lamp`，舊的鍵都不要動）。
- **預設關閉。關著的時候完全不建立 WebSocket**（不能讓一般訪客跳出本機存取詢問）。
- 手機、平板（`matchMedia("(pointer: coarse)")`）不顯示這個開關，因為 PenlightSync 只在電腦上。
- 打開時：連 `ws://127.0.0.1:51730/ado`；連上後依第 1 節送 `state`，在 `frame()` 裡判斷要不要送（不能每格都送）。連不上就每 5 秒重試，最多試 1 分鐘，之後停下來並把開關旁的狀態寫成「找不到 PenlightSync」，使用者再按一次才重試。
- 開關文字旁顯示小狀態：`連線中…`、`已連動`（收到 `hello` 且 `lamp` 是 `linked`）、`App 已開，手燈未連`、`找不到 PenlightSync`。第一次連上時跳 toast「已連上 PenlightSync」。
- 程式註解照 ado-guide 現有風格：台灣繁體中文、白話。

**做完的標準：**

- 開關關著：重新整理後 `performance.getEntriesByType("resource")` 和 Network 面板裡**沒有任何到 127.0.0.1 的連線**。
- 沒開 PenlightSync 時打開開關：網站照常可用，1 分鐘後停止重試；Console 只會有瀏覽器自己印的連線失敗訊息，沒有程式錯誤。
- 用步驟 1 的測試伺服器（或 PenlightSync）記錄收到的訊息：換歌、暫停、0.5 倍速、跳到別句、拖動進度條都會送；一秒不超過 5 則；離開歌曲頁會送 `stop`。
- `node --check app.js`、`node scripts/build.mjs "$TMPDIR/ado-dist"` 通過。

## 5. 禁止事項

1. **不能改手燈的藍牙協議和加密**（`PenlightProtocol.swift`、`PenlightCore.cs` 裡的加密部分），也不能改寫入的節奏（送出後等回覆）。
2. **伺服器只能綁 127.0.0.1**，不能開放區網或網際網路；不能連到任何外部伺服器。
3. **螢幕模式要和 v1.6.0 一模一樣**，而且仍是預設值；不能改既有設定的 UserDefaults 鍵名和預設值。
4. **網站預設不連線**；網站不能傳歌曲狀態以外的任何資料（不能有使用者資料、瀏覽紀錄）。不能改 ado-guide 既有的 localStorage 鍵名、網址、歌曲資料和歌詞。
5. **網站裡不能放手燈協議或加密的程式碼**（協議參考自 GPL-3.0 專案，放進網站會牽動網站的授權）。網站只送 JSON。
6. 不能加新的外部 CDN、npm 套件；PenlightSync 只用系統內建框架（Windows 現有的 NAudio 除外）。
7. **不能 commit、push、發 GitHub Release、上傳新的 zip**，除非使用者在對話裡明確同意；兩個 repo 都一樣。
8. 不能刪除檔案；暫存放 scratchpad 或各 repo 已被忽略的資料夾。
9. 不能宣稱沒做過的驗證（實機、Windows、Safari）已經通過。

## 6. 遇到這些情況先停下來問使用者

- 步驟 1 Chrome 連不上，或需要使用者做我們沒預期的設定。
- 埠 51730 在使用者的電腦上被別的程式佔用。
- 需要改動禁止清單裡的東西，或第 1 節的協議需要改。
- 實機測試時手燈斷線、亂閃或卡住。
- 同一個錯誤換方法重試一次還是失敗。
